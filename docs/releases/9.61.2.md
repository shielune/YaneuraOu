the two files the `explain` command reads are now attached to the release, so the `-explain` builds work as soon as they are downloaded. Nothing else changes from 9.61.1: the same two builds of every NNUE package and Windows engine (plain, and `-explain`), and the same engine source.

- **The files.** `hce-progress.bin` (1,202,212 bytes, a network that guesses how many moves the game has left) goes to the `HceProgressFile` option, and `hce-explain.bin` (977,072 bytes, the model that splits an evaluation into material, speed, king safety, piece activity and tempo) goes to `HceExplainFile`. The table below gives their SHA-256. They are the model described in the [9.61.0 notes](https://github.com/shielune/YaneuraOu/releases/tag/v9.61.0), which also say how close it is to NAGISA_V4 and where it says least.
- **They go together.** The model records which progress network it was fitted against and prints no parts if the other file is not that one. `hce-progress.bin` is not the `progress.bin` that NAGISA needs next to `nn.bin`; do not rename it to that.
- **Checked.** An engine built from the source of this release loads both files from the repository and prints `parts` for `explain moves 2g2f 3c3d`. The progress fingerprint computed from `hce-progress.bin` is the one recorded in `hce-explain.bin`.
