a single bug-fix release for the multi-threaded DfPn mate solver
(`mate-pthread`). Every package is otherwise identical to 9.60.1.

- **`mate-pthread` died with `RuntimeError: divide by zero` whenever it solved a
  position quickly.** The pthread variant runs the DfPn search on a `std::thread`
  and polls it every 100 ms, printing a PV line whose `nps` is
  `nodes * 1000 / elapsed`. When the mate is found before the first poll, the wait
  loop never executes, so the mandatory final PV output divides by an elapsed time
  of **zero** — which WASM traps, killing the search thread. `go mate` then never
  returns, and every later request on the same engine instance hangs behind it.
  Practical positions reach this path routinely: an 11-ply mate costs 0-5 ms of
  engine CPU, far below the first 100 ms poll, so the bug is hidden on the hard
  tsume problems that take longer than one poll interval to solve. `nps` is now
  computed against a floor of 1 ms, matching the `yaneuraou-search.cpp` idiom.

The single-threaded `mate-cfworkers` build calls `mate_dfpn` synchronously and
never enters that loop, so it was never affected — switching to it is a viable
workaround for anyone who cannot upgrade.
