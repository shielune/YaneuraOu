つようら王11 mini / micro の評価関数を使うための WASM パッケージを追加しました。評価関数は別途ダウンロードが必要です。エンジン本体は GPLv3、公式記事で公開された `nn.bin` と `progress.bin` は MIT License です。

**訂正:** この版で公開した `ka4096` / `ka2048` の WASM パッケージは、公式のつようら王11と別の構造 (`SFNN_ka2_4096_7_64_progress8x` / `SFNN_ka2_2048_7_64_progress8x`、shortcut 項あり) でビルドしてあります。公式の `nn.bin` を正しい位置で読めず、評価値が壊れた状態で探索します。**この版の `ka4096` / `ka2048` (通常版・`-explain` 版・ブラウザ版・Node.js 版) は使わないでください。** 以前この文書に書いていた確認値 (mini cp 76 / 113,918 nodes / `6i7h`、micro cp 15 / 4,476,254 nodes / `4g4f`) も、その誤った構造のビルドで取ったものなので無効です。ソースは公式と同じ `SFNN_ka2_*_8_64_progress8x` に直しました (下の「修正後の確認」を参照)。`ka4096` / `ka2048` 以外のパッケージは、名前も構造も変えていません。

- ブラウザ向け `pthread-ka4096` / `pthread-ka2048` と、Node.js 向け `node-ka4096` / `node-ka2048` を追加しました。それぞれ通常版と `-explain` 版を配布します。既存の NNUE ネットワークとは互換性がありません。
- mini は公式名 `SFNN_ka2_4096_8_64_progress8`、micro は `SFNN_ka2_2048_8_64_progress8` に対応します。公開した版のビルド名は `SFNN_ka2_*_7_64_progress8x` で、公式とは別の構造でした。H1 が 8 の倍数のときは shortcut 項を持たない、という規則を生成器に入れ、ソースの名前を末尾に `x` を付けた `SFNN_ka2_4096_8_64_progress8x` / `SFNN_ka2_2048_8_64_progress8x` に直しました。`x` は進行度係数を外部の `progress.bin` から読む指定で、`ek` と違い相入玉専用バケットを追加しません。
- `nn.bin` と `progress.bin` を両方 `EvalDir` に配置し、`FV_SCALE=24` を指定してください。新規パッケージのローダーの `fvScale` 既定値も 24 です。評価関数は [やねうら王の公式配布記事](https://yaneurao.fanbox.cc/posts/12761272) から取得できます。WASM のアーカイブには同梱しません。2 ファイルの合計は mini が 8,714,476 bytes、micro が 4,867,714 bytes です。
- 新しい層サイズに必要な WASM SIMD の affine カーネルを追加しました (公開した版の `7_64` 用)。また、新規4パッケージのスレッドごとのスタックを 16 MiB にしました。2 MiB の検証ビルドではスタック越境が検出され、検出を無効にした版では履歴テーブルを壊して探索結果が変わっていました。既存パッケージのスタック指定は変更していません。ソースでは `8_64` の形状でカーネルを見直し、スタックは実測した最小値 (mini 約 4.5 MiB、micro 約 2.5 MiB) に余裕を持たせた 8 MiB に下げました。
- 新規パッケージの線形メモリは初期 256 MiB / 最大 4 GiB、事前生成する worker pool はブラウザ版が 8、Node.js 版が 32 です。最大値は端末で確保できるメモリ量の保証ではありません。評価関数の読込時のコピー、探索履歴、定跡、hash、スレッドのメモリも必要です。

HCE のモデルファイルと `explain` / `go explain` の出力形式は 9.61.6 から変更していません。`-explain` 版で内訳を使う場合は、従来どおり同じリリースの `hce-progress.bin` と `hce-explain.bin` をそろえて読み込ませてください。

**公開前の実行確認 (無効)。** 公開時には、Linux arm64 上で CI run [38622893117](https://github.com/shielune/YaneuraOu/actions/runs/38622893117) の成果物を使って、mini / micro の Node.js 版とブラウザ pthread 版の計8構成を確認したと書いていましたが、上の訂正のとおり、確認に使ったのは誤った構造のビルドです。確認値は取り下げます。

**修正後の確認 (修正後のソース、公開済みアセットではない)。** Linux x86-64 上で、公式配布の `nn.bin` と `progress.bin`、初期局面、`FV_SCALE=24` / `Threads=1` / `USI_Hash=64` の `go depth 14` を測りました。ネイティブ (SSE4.2、AVX2、SIMD なし) と、WASM の Node.js 版 (Node.js 26.5.0、Emscripten 3.1.43) およびブラウザ pthread 版 (Chromium 154.0.8037.0、Emscripten 5.0.5)、それぞれ通常版と `-explain` 版の計8構成で、score・nodes・`bestmove` が一致しました。mini は cp 60 / 55,202 nodes / `bestmove 2g2f`、micro は cp 68 / 55,317 nodes / `bestmove 2g2f` です。explain 版4構成では、HCE の2モデルの読込、`explain moves 7g7f 3c3d` の3局面、`go explain depth 6` の `root` / `pv` / `leaf` と `done`、5項目の有限な数値を確認しました。単一局面・1スレッドでの確認で、対局による棋力評価ではありません。Threads=4 のブラウザ版が動くことは確認しましたが、値は比べていません。他のブラウザ、macOS / Windows / Linux arm64 / モバイルでの実行は検証していません。
