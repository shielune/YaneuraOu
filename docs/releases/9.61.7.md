つようら王11 mini / micro の評価関数を使うための WASM パッケージを追加しました。評価関数は別途ダウンロードが必要です。エンジン本体は GPLv3、公式記事で公開された `nn.bin` と `progress.bin` は MIT License です。

- ブラウザ向け `pthread-ka4096` / `pthread-ka2048` と、Node.js 向け `node-ka4096` / `node-ka2048` を追加しました。それぞれ通常版と `-explain` 版を配布します。既存の NNUE ネットワークとは互換性がありません。
- mini は公式名 `SFNN_ka2_4096_8_64_progress8`、micro は `SFNN_ka2_2048_8_64_progress8` に対応します。このフォークの生成器は最初の中間層を「出力数 − 1」で指定するため、ビルド名はそれぞれ `SFNN_ka2_4096_7_64_progress8x` / `SFNN_ka2_2048_7_64_progress8x` です。末尾の `x` は進行度係数を外部の `progress.bin` から読む指定で、`ek` と違い相入玉専用バケットを追加しません。
- `nn.bin` と `progress.bin` を両方 `EvalDir` に配置し、`FV_SCALE=24` を指定してください。新規パッケージのローダーの `fvScale` 既定値も 24 です。評価関数は [やねうら王の公式配布記事](https://yaneurao.fanbox.cc/posts/12761272) から取得できます。WASM のアーカイブには同梱しません。2 ファイルの合計は mini が 8,714,476 bytes、micro が 4,867,714 bytes です。
- 新しい層サイズに必要な WASM SIMD の affine カーネルを追加しました。また、新規4パッケージのスレッドごとのスタックを 16 MiB にしました。2 MiB の検証ビルドではスタック越境が検出され、検出を無効にした版では履歴テーブルを壊して探索結果が変わっていました。既存パッケージのスタック指定は変更していません。
- 新規パッケージの線形メモリは初期 256 MiB / 最大 4 GiB、事前生成する worker pool はブラウザ版が 8、Node.js 版が 32 です。最大値は端末で確保できるメモリ量の保証ではありません。評価関数の読込時のコピー、探索履歴、定跡、hash、スレッドのメモリも必要です。

HCE のモデルファイルと `explain` / `go explain` の出力形式は 9.61.6 から変更していません。`-explain` 版で内訳を使う場合は、従来どおり同じリリースの `hce-progress.bin` と `hce-explain.bin` をそろえて読み込ませてください。

公開前の実行確認は、Linux arm64 上で CI run [38622893117](https://github.com/shielune/YaneuraOu/actions/runs/38622893117) の成果物を使って行いました。mini / micro の Node.js 版 (Node.js 26.5.1、Emscripten 3.1.43) とブラウザ pthread 版 (Chromium 154.0.8037.0、Emscripten 5.0.5)、それぞれ通常版 / explain 版の計8構成で、起動、`progress.bin` の読込、`FV_SCALE=24` / `Threads=1` / `USI_Hash=64` の実値を確認しました。初期局面の `go depth 14` は全構成で同条件のネイティブ版と一致し、mini は cp 76 / 113,918 nodes / `bestmove 6i7h`、micro は cp 15 / 4,476,254 nodes / `bestmove 4g4f` でした。各銘柄の読み筋も構成間で一致しました。explain 版4構成では、HCE の2モデルの読込、`explain moves 7g7f 3c3d` の3局面、`go explain depth 6` の `root` / `pv` / `done` と5項目の数値出力を確認しました。これは単一局面・1スレッドでの確認であり、対局による棋力評価ではありません。複数スレッド、他のブラウザ、macOS / Windows / モバイルでの実行は検証していません。
