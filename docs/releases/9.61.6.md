`explain` の 5 項目の合計が、探索の評価値が大きい局面で小さく出すぎる問題を改善するため、HCE のモデルファイル `hce-explain.bin` を差し替え、合計の大きさに応じた倍率 `gain` を加えました。`explain` や `go explain` の `parts` を読んでいる利用者は、このリリースの 2 つのモデルファイルとエンジンに更新してください (出力の形式は変わらず、値が変わります。破壊的変更ではありません)。

- `hce-explain.bin` を新しくしました。隠れ層は 128 から 256 になり、ファイルは 977,072 バイトから 2,183,936 バイトになります (大半は玉の安全度のネットワークです)。SHA-256 は `99f520d2e34f0a90d2a9733daabb5e407dafe80d34afaa46841f667032e7608a` です。学習の行には、対局の生データから抜いた王手中の局面 4,549,283 行を加えました。
- `hce-progress.bin` は変わりません (SHA-256 は `6a4ba678cf82e6e90cc677d4f869f2a8529efd1edd9e14a0ea5f11434dea6b00`)。モデルは進行度ファイルとの対で学習してあり、指紋が合わないと内訳は出ません。この Release に付いた 2 つをそろえて使ってください。2 つはエンジンのアーカイブには入っていません。
- モデルファイルに任意の節 `gain` を加え、エンジンが読むようにしました。値は 14 個で、5 項目の合計の大きさ (絶対値) の位置が 7 個、その位置での倍率が 7 個です。位置の間は直線で結び、端の外は端の倍率を使います。エンジンは 5 項目を計算したあと、合計の大きさから倍率を求めて、5 項目すべてに同じ倍率を掛けます。足した値は、今までどおり合計の倍率倍です。
- 同梱の `gain` は、合計の大きさ 0 / 250 / 500 / 1000 / 1500 / 2000 / 3000 で、倍率 0.91 / 0.93 / 1.08 / 1.18 / 1.24 / 1.13 / 0.98 です。倍率を決めるときの条件 (1000〜3000 の局面で合計が NAGISA_V4 の評価値の 0.90 以上、どの大きさの帯でも NAGISA_V4 の評価値 ÷ 合計が 0.85 以上) は、開発側で決めた数字です。
- `gain` が無いモデルファイルは、倍率 1 として読みます。キー名 (`material` / `tempo` / `threat` / `king_safety` / `mobility`)、`HCEXPL01` の版 (1)、`hce-progress.bin` は変わりません。9.61.5 までのエンジンは、知らない節を読み飛ばし、隠れ層の大きさもファイルの節から読む作りです。新しいファイルを古いエンジンに読ませる動作は、実機では確認していません。
- 変更は `explain` のコードとモデルの読み込みだけで、探索のコードには触れていません。これらのソースは `HCE_EXPLAIN=ON` のビルドにだけ入るため、`-explain` の付かない通常版のエンジンのソースは 9.61.5 と同じです。
- 測定は、学習に使っていない対局から抜いた 3000 局面を、NAGISA_V4 の explain 付きビルド (linux/amd64) で depth 12、MultiPV 3 で探索して行いました。8,794 本の読み筋の末端で、5 項目の合計 ÷ 探索値の中央値を比べると、探索値の大きさが 500〜1000 の帯で 0.646 から 0.706、1000〜2000 で 0.786 から 0.942、2000〜3000 で 0.903 から 1.010 になりました。詰みを返した 864 本で、合計が詰ます側の符号になる割合は 0.806 から 0.907 です。
- **改善していない範囲があります。** 探索値が 200〜500 の帯は 0.512 から 0.489 で、区間は重なっていますが上がっていません。3000 以上は 0.756 から 0.769 とほぼ同じです。探索値が 0〜200 の符号の一致も 0.648 から 0.639 で、改善していません。倍率は合計の大きさだけで決まり、序盤か終盤かでは変わりません。
- 公開前の確認は、次の範囲です。ワークフローと同じ形のハッシュ確認 (`shasum -a 256 -c`) が 2 つのファイルで通ること。linux/amd64 の KP256 の explain 付きビルドで `script/test_native_explain.ts` が通ること。学習側の Python との照合 (1000 局面、5 項目) で、`gain` ありは最大差 0.58、`gain` なしは最大差 0.54 で、どちらも整数への丸めの範囲に収まること。NAGISA_V4 (HalfKA2304) は linux/amd64 の explain 付きビルドで上の測定を行いました。測定は NAGISA_V4 だけで、ほかの NNUE の構成では測っていません。arm64 Linux、macOS、Windows、WASM での実行は検証していません。
