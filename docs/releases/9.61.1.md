every NNUE package and Windows engine now comes in two builds, side by side in this release: the plain one, and one with the `explain` command, whose file name ends in `-explain`. The Mate packages have no evaluation to explain and come in one build only.

- **Which to download.** `yaneuraou-wasm-pthread-kp256-v9.61.1.tar.gz` is the package as before, without `explain`. `yaneuraou-wasm-pthread-kp256-v9.61.1-explain.tar.gz` is the same package with an engine that also answers `explain`. The Windows engines are named the same way (`yaneuraou-windows-kp256-v9.61.1-explain.tar.gz`). Inside, the two differ only in the engine (`yaneuraou.wasm` and its loader, or the `.exe` files); `package.json` and the TypeScript loader are the same.
- **What `explain` does.** `explain moves 2g2f 3c3d` splits each position of a line into **material**, **speed** (who is closer to mating whom), **king safety**, **piece activity** and **tempo**, positive for Black, adding up to a model's estimate of NAGISA_V4's evaluation. It does not search and does not use the package's own network, so it works with any of the NNUE packages.
  - It reads two files, attached to this release: `hce-progress.bin` (1,202,212 bytes, a network that guesses how many moves the game has left, printed as `moves_left`) goes to the `HceProgressFile` option, and `hce-explain.bin` (977,072 bytes, the model) goes to `HceExplainFile`. The model records which progress network it was fitted against, and no parts are printed when the other file is not that one. `hce-progress.bin` is not the `progress.bin` that NAGISA needs next to `nn.bin`; do not rename it to that. Without the files `explain` prints the older linear breakdown. `HceSpeed` (off by default) also prints the eight numbers behind the speed part.
  - On 1,235,058 positions it was not fitted on, the estimate misses NAGISA_V4 by 416 root-mean-square, against 895 for always saying 0, and is within 500 on 85% of positions. It is better early than late: 183, 373 and 630 in the three thirds of NAGISA's own progress. The full account is in the [9.61.0 notes](https://github.com/shielune/YaneuraOu/releases/tag/v9.61.0).
- **What was checked.** The engine code is the same as in 9.61.0, which differs from this release only in how the builds are made. In 9.61.0 each piece of `explain` was compared with the Python that trained it, on thousands of held-out positions, and `explain` was run with both files in the KP256 Node.js package. On one SFNN build the `bench` node count is the same with the command in and out (272,452). The Windows `-explain` engines compile and link under MinGW (checked for KP256 and HalfKA1024); they have not been run.
- **9.61.0.** Every NNUE package in 9.61.0 has `explain` in it, under the plain name. From here on the plain name means without it. If you use `explain`, take the `-explain` files of this release; they replace 9.61.0.
- **Building it yourself.** `make YANEURAOU_EDITION=<nnue edition> HCE_EXPLAIN=ON`. It is off by default, and with it off the build has no `explain` command. The code is in `source/eval/hce/`.
