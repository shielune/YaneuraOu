`explain` の出力形式を整理し、探索のあとに読み筋を内訳つきで出す `go explain` を追加しました。**v9.61.3 までの `explain` の出力を読んでいる利用者は、このリリースで更新が必要です (破壊的変更)。**

- `parts` のキー名を `threat` / `mobility` / `king_safety` に改名しました (旧 `speed` / `activity` / `king`)。`material` と `tempo` は同名です。オプション `HceSpeed` も `HceThreat` に改名しました。旧名の別名は残していません。
- `top` の項目名は ASCII の英語識別子になりました。不正手は `info string` ではなく JSON の `error` 行で返し、最後に終端行 `{"done":true,"positions":N}` を必ず出します。`top 0` も使えます。出力はすべて ASCII です (UTF-8 は `\uXXXX`)。
- 旧線形内訳 (`black_pov`、`mobility`、`top` など) は `explain legacy` を付けたときだけ出し、項目は `linear_*` に改名しました。
- `go explain <通常の go 指定>` を追加しました (`HCE_EXPLAIN=ON` のビルドのみ)。探索のあと `bestmove` の直前に、MultiPV の全候補について `root` / `pv` / `leaf` の行を出します。`root` は現局面の生の値と静止探索後の値 (`qsearch_parts`)、`pv` は読み筋の全局面の静止探索なしの生の値、`leaf` は読み筋の末端局面を静止探索した後の値です。通常の `go` は変更ありません。
- 使い方の例: 取り合いの途中の局面は生の値だと大きく偏ります。たとえば飛車の交換では `material` が +941 になり、取り返した後に 0 へ戻ります。`pv` 行を読み筋に沿って追うと、この様子が見えます。
- 公開前の確認は、arm64 Linux のネイティブビルドでの実行のみです。通常、`legacy`、不正手、`top 0`、`go explain` の `root` / `pv` / `leaf`、および通常の `go` の探索ノード数が変わらないことを確かめました。amd64、macOS、Windows、WASM での実行は検証していません。

出力の詳細は [docs/explain_protocol.md](https://github.com/shielune/YaneuraOu/blob/v9.61.4/docs/explain_protocol.md) を参照してください。
